# 练习题：库存盘点 Agent

> 出题日期：2026-09-02
> 前置知识：六项考核清单（普通对话 / 结构化 JSON / 定义工具 / 解析 tool call / 执行回传 / loop 保护）
> 关联文档：[function-calling-guide-summary.md](./function-calling-guide-summary.md)（概念层复习用，**不是答案**）

## 一、题目场景

仓库 A 需要盘点。写一个 agent 程序接到任务后：自己找到库存文件 → 读取 → 计算 → 生成 JSON 报告存盘。

**新建 `cmd/inventory_agent/main.go` 完成，从空白文件开始写。**

给模型的最终任务描述（可直接用）：

> 盘点仓库 A 的库存，生成 JSON 报告并保存为 `report.json`。报告必须包含：仓库、商品种数、总件数、未盘点的商品列表、是否全部盘点完成。

## 二、硬性要求（对照六项考核）

| # | 考核项 | 本题要求 |
|---|--------|----------|
| 1 | 普通对话 | 程序开头先发起一次**无工具的普通对话**："用一句话说明你完成盘点任务的思路"，打印出来 |
| 2 | 结构化 JSON | 最终报告是**结构化 JSON**：自己设计 schema，`"type": "array"` 和 `"type": "boolean"` 字段各至少一个，解析进 Go 结构体后写盘 |
| 3 | 定义工具 | 至少 **5 个工具**：`search`、`read_file`、`calculator`、`list_files`（用 `os.ReadDir`）、`write_report` |
| 4 | 解析 tool call | 完整 agent loop：从 output 解析 `function_call`，支持单轮多个 |
| 5 | 执行并回传 | 执行工具 → 追加调用记录 + 结果（`call_id` 对应）→ 循环直到无调用 |
| 6 | loop 保护 | `maxSteps ≤ 5`、总超时（`context.WithTimeout`）、429/5xx 重试一次、工具错误作为字符串喂回让模型自愈 |

## 三、题目素材

### 1. 真实库存文件（已创建）

`data/inventory.txt`：

```
仓库A 库存清单（盘点日期：2026-09-02）
商品A | 数量：50
商品B | 数量：35
商品C | 数量：待盘点
商品D | 数量：12
```

⚠️ 注意"商品C"是**待盘点**——你的报告必须如实反映它（boolean 字段的来源）。

### 2. search 知识库要故意写错（错误处理素材）

你的 `search` 工具内部知识库**必须**这样配：

```
库存数据存放在 stock.txt          ← 故意的错误线索
团队成员名单存放在 team.txt
```

`stock.txt` 不存在。模型按线索读取会得到 file-not-found，必须自己恢复——`list_files` 就是留给它的自救通道。这段"失败 → 自愈"必须出现在你的运行日志里。

### 3. 工具安全约束

- `read_file`、`write_report`、`list_files` 只允许访问 `data/` 目录
- 路径防护：拒绝绝对路径、拒绝包含 `..` 的相对路径（`filepath.Clean` 检查）

## 四、验收标准（自测打勾）

```
□ data/report.json 存在且是合法 JSON，字段符合自己定义的 schema
□ 数值正确：商品种数=4，总件数=97，未盘点=["商品C"]，是否完成=false
□ 运行日志中能看到：至少一次工具失败（stock.txt not found）+ 模型自愈
□ 日志中至少 4 次工具调用，且包含 calculator 的调用
□ 未触发 maxSteps 强制中止
□ maxSteps / 超时 / 重试代码存在——能说出用什么方法验证它们真的能触发
□ 报告里 boolean 字段正确反映了"待盘点"的存在
```

## 五、里程碑路径（每步跑通再下一步）

- [ ] **里程碑 1 — 骨架**：client（Zen 网关）+ 无工具对话跑通
- [ ] **里程碑 2 — 结构化输出**：单独调通一次 `text.format json_schema`（拿一段写死的文字练手，先不进 agent）
- [ ] **里程碑 3 — 工具层**：5 个工具函数 + 注册表（map），在 main 里手动调用逐个测试打印结果
- [ ] **里程碑 4 — agent loop**：串起来跑通主任务
- [ ] **里程碑 5 — 保护层**：maxSteps / 超时 / 重试 / 错误喂回

## 七、两个提示（只到这里）

1. **里程碑 2 的坑**：如果把 `text.format` 和 `tools` 放进**同一个请求**，可能会收到 422——想想要不要把"agent 调查"和"结构化产出"拆成两步
2. **calculator 的问题**：模型可能不调用工具而自己心算——想想工具的 `description` 怎么写才能逼它用工具（验收要求日志里有 calculator 调用）
